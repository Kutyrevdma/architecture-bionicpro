# Архитектура слоя кэширования отчётов (S3 + CDN)

## Контекст

При повторных запросах исторических отчётов пользователи обращаются к одним и тем же данным. Это приводит к избыточным чтениям из аналитической базы (ClickHouse) и создаёт ненужную нагрузку на OLAP-контур.

## Подход

Для разгрузки аналитического хранилища добавлен промежуточный слой хранения готовых отчётов. Подготовленные файлы сохраняются в объектное хранилище и раздаются через CDN-слой.

## Состав решения

### Объектное хранилище

**MinIO (S3-совместимое)** используется для хранения уже сформированных отчётов.

Особенности:

* формат хранения — JSON;
* ключи вида: `reports/{user_id}/{date}.json`;
* длительное хранение исторических отчётов;
* доступ по HTTP через прокси-слой.

### CDN / Reverse Proxy

**Nginx** располагается перед объектным хранилищем.

Функции:

* отдача статических файлов;
* кэширование ответов от S3;
* снижение задержек при частых запросах;
* уменьшение количества обращений к хранилищу.

### Сервис отчётов

Backend-сервис выполняет роль координатора.

Логика работы:

* проверяет наличие файла отчёта в S3;
* при наличии возвращает ссылку на CDN;
* при отсутствии формирует отчёт из ClickHouse;
* сохраняет файл в S3;
* возвращает URL для загрузки.

Сервис не хранит файлы локально — только управляет их созданием и публикацией.

## Сценарий обработки запроса

1. Клиент запрашивает отчёт через frontend.
2. Запрос проходит через BFF в Reports Service.
3. Сервис определяет дату отчёта.
4. Выполняется проверка наличия файла в S3.

### Cache hit

Если файл уже существует:

* сервис возвращает ссылку на CDN;
* клиент загружает готовый JSON через Nginx.

### Cache miss

Если файл отсутствует:

* выполняется запрос в ClickHouse;
* формируется JSON-отчёт;
* файл сохраняется в S3;
* клиенту возвращается ссылка на CDN.

После этого все последующие обращения к тому же отчёту будут обслуживаться из кэша.

## Выдача файла

1. Frontend получает `report_url`.
2. Выполняется HTTP-запрос к CDN.
3. Nginx проверяет локальный кэш.
4. При необходимости запрашивает файл из MinIO.
5. Возвращает результат клиенту.

## Стратегия обновления

Данные обновляются пакетно (раз в сутки). Поэтому отчёты формируются с привязкой к дате.

Использование даты в имени файла позволяет:

* автоматически получать новый отчёт при смене дня;
* не выполнять явную инвалидацию кэша;
* хранить историю отчётов;
* применять политику ротации при необходимости.

При первом запросе нового дня файл создаётся заново и далее используется как кэшированная версия.
