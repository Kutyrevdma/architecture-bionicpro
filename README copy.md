# Руководство по запуску и валидации решения BionicPRO

В репозитории собраны результаты спринта (4 задачи), сведённые в единую микросервисную схему. Текущее состояние кода соответствует финальной итерации (Task 4), поэтому функциональность можно проверять комплексно после старта окружения.

## Зависимости

* Docker
* Docker Compose

## Старт окружения

1. **Инициализация сервисов**

   ```bash
   bash scripts/start_project.sh
   ```

   Скрипт выполняет сборку образов, поднимает контейнеры, применяет структуры БД (ClickHouse), активирует CDC‑конвейер (Debezium) и загружает тестовый набор данных.

2. **Точки доступа**

   * Web‑интерфейс: [http://localhost:3000](http://localhost:3000)
   * IAM (Keycloak): [http://localhost:8080](http://localhost:8080)
   * MinIO Console: [http://localhost:9001](http://localhost:9001)
     учётные данные: `minioadmin` / `minioadmin`

## Валидация функциональности

Для каждой части решения предусмотрен отдельный сценарий проверки. Скрипты демонстрируют ожидаемое поведение сервисов.

### Task 1 — Контур безопасности и BFF

Аутентификация и управление сессиями реализованы через Keycloak и промежуточный BFF‑слой.

**Запуск проверки:**

```bash
bash scripts/verify_task1.sh
```

Проверяется доступность BFF, корректность конфигурации IAM и защита API‑эндпоинтов.

### Task 2 — Подсистема отчётности

Формирование отчётов на базе OLAP‑хранилища (ClickHouse) и ETL‑логики.

**Запуск проверки:**

```bash
bash scripts/verify_task2.sh
```

Сценарий формирует отчёт для тестового пользователя `user1` и возвращает результат в формате JSON.

### Task 3 — Кэширование и раздача

Оптимизация нагрузки через сохранение отчётов в S3‑совместимом хранилище и публикацию через Nginx (CDN‑паттерн).

**Запуск проверки:**

```bash
bash scripts/verify_task3.sh
```

Выполняется запрос отчёта, валидируется наличие `report_url`, затем файл скачивается через CDN.

### Task 4 — CDC поток данных

Реализация Change Data Capture: потоковая синхронизация из CRM (Postgres) в ClickHouse.

**Запуск проверки:**

```bash
bash scripts/verify_task4.sh
```

Скрипт добавляет запись в Postgres и проверяет её появление в аналитических данных без ручного запуска ETL.

## Дерево каталогов

* `frontend/` — клиентское приложение (React)
* `bionicpro-auth/` — BFF и модуль аутентификации
* `reports-service/` — API отчётности
* `dags/` — DAG‑сценарии Airflow (историческая часть Task 2)
* `scripts/` — скрипты запуска и тестирования
* `TaskX/` — артефакты по отдельным задачам
